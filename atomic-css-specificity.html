Atomic CSS · cascade mechanics

How atomic CSS engines force one rule to beat another

StyleX and Truss both ship one class per declaration, so two classes on the same element can end up fighting over the same property. Both resolve it with the same priority number, computed from the same CSS shorthand graph — but StyleX expresses that number in the cascade and Truss expresses it in emission order. Here is what that costs, live.

Specificity, in three numbers

When two rules set the same property on one element, the browser scores each selector as a triple and compares it left to right, like a version number. It never carries: one ID outranks any number of classes.

That last one is the whole hack. #\# is an escaped #, so it means "an element whose id is literally #". Nothing has that id, so :not(#\#) excludes nothing and matches every element — but the browser still counts the ID inside it. It buys weight and changes nothing else. Only a tie falls through to source order, last rule wins.

Scenario 1

A longhand has to beat a shorthand

The author writes margin: 0 and then margin-bottom: 14px. In an atomic engine those are two separate classes, and margin and marginBottom are different keys — so neither can cancel the other in JavaScript. Both classes land on the element and CSS has to pick a winner.

margin: 0 · margin-bottom: 14px
the next block
margin-bottom: 14px wins — 14px gap 410 longhand  vs  110 shorthand
StyleX

Encodes a priority number into every selector. Longhands sit at 3–4, shorthands at 1–2, so the longhand outranks whatever order they get emitted in. This is StyleX's @layer polyfill — the same downlevelling Lightning CSS does.

/* longhand — written first on purpose */
.x1u7kmwd:not(#\#):not(#\#)
         :not(#\#):not(#\#) {
  margin-bottom: 14px;   /* (4,1,0) */
}

/* shorthand — later in the file, and
   still loses */
.x1ghz6dp:not(#\#) {
  margin: 0;             /* (1,1,0) */
}
4 beats 1 at the first position, so the comparison stops there. Source order never gets consulted. Cost: 10 characters per copy, 1,440 copies across the stylesheet.
Truss

Never emits the shorthand at all. m0 expands to four longhands in the config, so the collision happens on the same JavaScript key and the loser is gone before a class name is ever chosen.

// Css.json — m0 is not `margin: 0`
"m0": { "defs": {
  "marginTop": 0,  "marginRight": 0,
  "marginBottom": 0, "marginLeft": 0 } }

// Css.m0.mb_14px.$ → Object.assign
{ marginTop: 0, marginRight: 0,
  marginLeft: 0,
  marginBottom: 0,        // overwritten
  marginBottom: "14px" }     // survives

/* four plain classes, no conflict */
.t-mt0  { margin-top: 0; }     /* (0,1,0) */
.t-mb_14px { margin-bottom: 14px; }
No two classes ever set the same property, so there is nothing to arbitrate. For the shorthands Truss does keep — gap, border-color, inset — it sorts the stylesheet by priority instead. Same answer, zero bytes.

Scenario 2

A media-query variant has to beat its base rule

gap: 22px normally, gap: 0 under 900px. Here's the catch: wrapping a rule in @media adds no specificity at all. The variant and the base rule score identically. Both engines fix it the same way — and it isn't :not(#\#): they repeat the class name.

two
three
base rule applies — gap: 22px 020 variant  vs  010 base

The real @media rule is live too — narrow this window past 900px and the gap closes on its own.

StyleX

Repeats the class name. It already carries the property-tier padding from scenario 1; the doubling is what settles base versus variant.

.xmt3bw4:not(#\#):not(#\#) {
  gap: 22px;          /* (2,1,0) */
}

@media (max-width: 900px) {
  .x1dengtm.x1dengtm:not(#\#)
                    :not(#\#) {
    gap: 0px;         /* (2,2,0) */
  }
}
Same tier at position one; the doubled class breaks it at position two.
Truss

Repeats the class name. Identical technique — and since there's no property tier to carry, that's the entire selector.

.g_22px {
  gap: 22px;          /* (0,1,0) */
}

@media screen and (max-width: 900px) {
  .tabletanddown_g_0px
  .tabletanddown_g_0px {
    gap: 0px;         /* (0,2,0) */
  }
}
Doubling a name already in the selector costs the length of that name; appending :not(#\#) costs a flat 10 characters every time.

Wait — if Truss sorts the stylesheet, why double anything?

Because sorting only decides a tie. Truss's stylesheet is ordered by a priority key in which @media scores +200 and :hover scores +130, so a media rule is meant to beat a hover rule. But specificity is checked first, and it doesn't care about that key:

.h_red:hover 020 wins on specificity…
@media { .sm_blue } 010 …however late it appears
@media { .sm_blue.sm_blue } 020 now tied — the sort decides

So the doubling isn't there to win. It's there to stop specificity from deciding, so that the priority sort can. That's the whole Truss model in one line: specificity is levelled, and order carries the meaning. StyleX inverts it — specificity carries the meaning, and order is made irrelevant.

Same scheme, two different media

Neither engine improvised. Both classify every property against the CSS shorthand graph and assign it a priority, and they land on the same ladder — StyleX's tier n is Truss's priority n × 1000.

Property classExampleStyleXTruss
shorthand of shorthandsmargin, bordertier 11000
shorthand of longhandsgap, insettier 22000
logical longhandmargin-block-endtier 33000
physical longhandmargin-bottom, toptier 44000
pseudo-element::after+5…7+5000

The difference is where that number lives. StyleX puts it in the cascade. With useCSSLayers switched on it emits real @layer stylex.priority1 { … } blocks; switched off — the default for every bundler plugin but Bun — it downlevels those layers into repeated :not(#\#), exactly the way Lightning CSS and PostCSS polyfill layers. Either way the priority rides inside the selector, where emission order can't disturb it. Layers aren't free either: layered CSS always loses to unlayered CSS, so turning them on lets a plain reset stylesheet override StyleX.

Truss puts it in emission order. It emits one stylesheet and re-orders that stylesheet itself, so source order is something it owns and the priority can live in a sort key that costs nothing. It reaches for specificity only where specificity would otherwise overrule that key — the doubled class above.

The documented reason for StyleX's priorities is correctness, not build layout: "the layers exist to ensure that various different styles have the right specificity. We need margin-top to win over margin for example." — nmn, StyleX maintainer. Order-independence is a property of the approach; StyleX doesn't state it as the motivation.

Postscript

None of this is what decides the size

StyleX has a switch that removes the whole hack. Set useCSSLayers and it emits real @layer blocks instead — all 1,440 copies of :not(#\#) vanish, and every one of the 499 rules is otherwise byte-identical. Here is what that buys:

StyleXRawBrotli
specificity padding (default)40,4307,008
useCSSLayers30,4706,938
saving−9,960 (−24.6%)−70 (−1.0%)

A quarter of the raw stylesheet — and seventy bytes on the wire. 1,440 copies of one 10-character literal is the most compressible thing you can put in a file. So the hack this whole page is about is close to irrelevant to what a browser downloads.

What actually decides it: class-name entropy

Truss still ships a smaller stylesheet than StyleX-on-layers — 5,064 against 6,419 brotli. Give both engines the same naming scheme and almost all of that gap disappears.

Roughly 91–93% of the compressed gap is naming, not CSS. And the raw numbers point the other way: StyleX emits less stylesheet than Truss in every condition — 22,111 bytes of canonical rules against 23,906. Its content is more compact. It loses on encoding alone.

StyleX's ~490 class names are 8-character content hashes — x1u7kmwd, xmt3bw4, x1dengtm. Near-maximal entropy: no shared substrings, no relationship to anything else in the file, about 4 KB that a compressor cannot touch. Truss's are mb_14px, mb_16px, mb_18px, g_22px. They share prefixes with one another, and each one restates the declaration it heads — .mb_14px { margin-bottom: 14px; } hands the dictionary the same fact twice.

So the intuition that short class names win is the wrong reading. Truss's names are longer than StyleX's — 9.2 characters against 7.2 — and they make the uncompressed stylesheet bigger. They win because they are predictable, which is the opposite property from short. Hashing is what makes a name incompressible, and hashing is what you do to make names short.
